# Авито → Telegram: Winx / Винкс

Поиск по всей России, все категории, круглосуточно. Расписание: минуты 7, 22, 37 и 52 каждого часа. Стандартный Linux runner GitHub Actions бесплатен для публичного репозитория, но запуски могут задерживаться или пропускаться.

## Настройка

1. Создайте бота через @BotFather и нажмите «Запустить» в чате с ботом.
2. Settings → Secrets and variables → Actions: добавьте секреты `TELEGRAM_BOT_TOKEN` (токен BotFather) и `TELEGRAM_CHAT_ID` (ID вашего чата с ботом).
3. Actions → Avito monitor → Run workflow. Включённый `probe` проверяет только доступ к Авито без Telegram и сохранения истории. Выключенный — запускает мониторинг.

Чтобы узнать chat ID, отправьте боту сообщение, затем выполните этот Python-скрипт на своём компьютере. Ввод токена скрыт; скрипт выводит только ID чатов. Не публикуйте токен в репозитории или переписке.

```python
import getpass, json, urllib.request
token = getpass.getpass('Токен бота: ')
with urllib.request.urlopen('https://api.telegram.org/bot' + token + '/getUpdates') as r:
    result = json.load(r)
print(sorted({u['message']['chat']['id'] for u in result['result'] if 'message' in u}))
```

Первый успешный полный проход запоминает объявления без рассылки. Затем отправляются новые ID: название, цена и ссылка. Telegram может показать превью ссылки; отдельная загрузка фото пока не реализована. История и очередь сообщений хранятся в ветке `state`, без токена и chat ID. Не удаляйте эту ветку.

## Ограничения

- Парсер требует проверки на реальной HTML-выдаче Авито из GitHub. Блокировка, капча, пустая выдача или изменение разметки вызывают ошибку, история не сбрасывается. Капча не обходится; платные прокси не используются.
- Обходятся доступные страницы обоих запросов с паузой; лимит — 100 страниц на запрос. При превышении проход считается неполным. Используется выдача самого Авито, включая совпадения в описании и возможные расширенные результаты.
- Новый ID означает ранее не встречавшееся объявление. Старое объявление, вернувшееся в выдачу позже, тоже может попасть в рассылку. Истинная дата создания не проверяется; удалённые между проверками объявления можно пропустить.
- Неотправленные сообщения остаются в очереди. При аварийном завершении после отправки, но до сохранения истории возможен повтор.
- GitHub отключает расписания публичных репозиториев после 60 дней отсутствия активности. Проверяйте Actions и включайте workflow снова при необходимости.
